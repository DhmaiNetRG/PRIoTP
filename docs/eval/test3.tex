\chapter{Test 3: Reliability under packet losses}
In this section we study the effect of different packet loss rates in case of
weakly reliable and non-realiable transport.

\section{Evaluation scenario}
The packet loss was created with our transport layer implementation which is
capable to simulate artificial packet loss and delays. It's good to notice
however that this is not the most realistic situation as packet loss is only
happening on the link from server to client. This means that when a weakly
realiabile subscriptions are used all acknowledgements are not experiencing any
packet loss except in case that happens naturally. The clients have packet loss
ratios of 0.33, 0.10, 0.01, and 0.

The statistics for camera data when weakly reliable transport is turned on are shown in table
\ref{table:task3-camera-b} and for temperature data in table
\ref{table:task3-temp-b}. We observe negligble decrease in the packet loss
rate with the camera sensor while with temperature sensor there are no packet
losses. The assumption behind this is that the high volume traffic camera
sensors publish updates periodicly at a rate so high that the reliability
mechanism will cause messages to trash at server while the server is busy to
deliver the retransmission. The low traffic volume flows like the updates from
temperature sensors are delivered without packet losses
